# 🧪 精馏塔软测量时序预处理 — 技术分析报告

> 石油化工 · 精馏塔 · 时序数据预处理 · 软测量 · 特征工程

---

## 一、项目背景

### 1.1 业务场景

在炼化/石化行业中，**精馏塔**是最核心的分离单元。其**塔顶产品纯度**是衡量产品质量的关键指标，但实时纯度通常无法通过硬件传感器直接测得——在线气相色谱（GC）分析仪成本高、维护量大、采样间隔长（通常 10-30 分钟一次）。

**软测量（Soft Sensor）** 技术应运而生：利用易测的过程变量（温度、压力、流量、液位），通过数学模型实时推算产品纯度。

### 1.2 核心痛点

精馏塔时序数据在实际工业场景中面临以下挑战：

| # | 问题 | 真实来源 | 对建模的影响 |
|---|------|---------|------------|
| 1 | **传感器噪声** | 热电偶热噪声、电磁干扰 | 降低信噪比，模型学到的可能是噪声 |
| 2 | **多变量时延** | 进料变化需经 N 块塔板才影响纯度 | 变量间因果关系存在时间错位 |
| 3 | **缺失值** | 仪表掉线、采样故障 | 破坏序列连续性 |
| 4 | **工况切换** | 负荷调整、产品牌号切换 | 统计分布非平稳 |
| 5 | **传感器退化** | 漂移、膜片污染、卡死 | 测量值偏离真值 |

**其中，"时序截取"是预处理中最关键但最容易被忽略的环节。** 截取策略的选择直接决定了模型能否正确捕获变量间的因果时序关系。

## 二、技术方案调研

### 2.1 技术栈选型

| 方案 | 优势 | 劣势 | 本项目选择 |
|------|------|------|-----------|
| **Node.js** | 环境现成、快速原型、展示 vibecoding | 非数据科学生态主流 | ✅ MVP 方法论验证 |
| **Python** (pandas/numpy/scikit-learn) | 工业标准、生态完善 | 需额外装环境 | ⏳ Phase2 迁移目标 |

**选型决策：** 本项目的核心价值在方法论而非语言，先用 Node.js 快速验证后，迁移至 Python 生产版。

### 2.2 模型选型调研

#### 候选模型对比

| 模型类型 | 具体模型 | 精馏塔适用性 | 选择理由 |
|---------|---------|------------|---------|
| **传统机器学习** | 随机森林 (RF) | ⭐⭐⭐⭐⭐ | **主模型**：非线性、特征重要性、抗过拟合 |
| **传统机器学习** | XGBoost | ⭐⭐⭐⭐⭐ | **Phase2**：精度略高但调参复杂 |
| **传统机器学习** | PLS（偏最小二乘） | ⭐⭐⭐⭐ | 化工经典，线性方法 |
| **深度学习** | LSTM/GRU | ⭐⭐⭐⭐ | 时序建模优势，但需大量数据 |
| **深度学习** | 1D-CNN | ⭐⭐⭐ | 可提取局部模式 |
| **强化学习** | PPO/DQN | ⭐ | 控制优化问题，非回归预测 ❌ |

#### 为什么选 RF 而不是 LSTM？

```
决策树分析：

数据规模：精馏塔软测量典型样本量 200-2000 条
    ├── RF: ✅ 在此量级表现优异，不需要大量调参
    └── LSTM: ❌ 需要万级以上数据才能发挥优势

可解释性：
    ├── RF: ✅ Feature Importance + SHAP 直接回答"哪个变量影响最大"
    └── LSTM: ❌ 黑箱，工业验收困难

部署成本：
    ├── RF: ✅ DCS 系统可轻松承载
    └── LSTM: ❌ 需要 GPU 或优化推理引擎

结论：RF 是精馏塔软测量 MVP 的最佳选择
```

#### 为什么 RL 不适用

强化学习解决的是**控制优化**问题（如何调节参数使目标最优），而软测量解决的是**状态估计**问题（当前纯度是多少）。这是两个不同的任务。RL 对应提示词中的"方向三"，在完成方向一（预处理+预测）后可作为进阶方向。

### 2.3 大规模数据处理方案

| 策略 | 方法 | 适用场景 |
|------|------|---------|
| 流式滑动窗口 | 维护滚动统计量，分批处理 | 实时预处理管线 |
| 分块 + 列式存储 | Parquet 格式按时间分区 | 历史数据批处理 |
| 下采样桥接 | 先降采样再分析趋势 | 长周期回顾 |
| Dask/Spark | 分布式并行计算 | 全厂级数据挖掘 |

### 2.4 极端脏数据应对策略

除本项目模拟的噪声和缺失外，工业现场还需应对：

- **传感器卡死**：检测滑动窗口方差 < 阈值
- **漂移退化**：冗余传感器交叉验证 + 长期趋势偏离检测
- **多模态污染**：先工况识别聚类，再分模式处理
- **率限制违例**：物理约束校验（温度变化速度上限）
- **幽灵数据**：物料/能量平衡闭合校验

## 三、数据生成策略

### 3.1 精馏塔工艺背景

以**苯-甲苯精馏塔**为模拟对象，关键变量包括：

```
进料流量 F(t) ──► 塔内汽液负荷变化
塔顶温度 T(t) ──► 反映塔顶轻组分含量（塔顶产品品质）
回流流量 L(t) ──► 精馏段分离能力
塔釜温度 B(t) ──► 塔底热负荷与组成
纯度 x_D(t)   ──► 目标变量（塔顶产品纯度）
```

### 3.2 简化机理模型

纯度生成采用**基于 Fenske 方程修正的非线性模型**：

```
x_D = f(R, α, T_top, F, B)

其中：
- R = L/D 回流比（分离能力核心因素）
- α = 2.4 - 0.015*(T_top - 80) 温度依赖的相对挥发度
- 引入非线性：高回流比下边际收益递减 exp(-R)
- 加入温度、进料、交互效应的修正项
```

### 3.3 真实问题注入

| 问题 | 参数 | 效果 |
|------|------|------|
| 高斯噪声 | σ ≈ 0.3°C / 3 kg/h | 模拟传感器热噪声 |
| 脉冲干扰 | 概率 0.5%，幅度 2°C | 模拟电磁干扰 |
| 时延 | F:15步, T_top:3步, L:5步, B:10步 | 模拟化工过程动态 |
| 随机缺失 | 概率 2% | 模拟数据丢包 |
| 连续缺失 | 概率 0.5%，长度 3-6步 | 模拟仪表掉线 |
| 工况阶跃 | 进料量 +40 kg/h 于中点 | 模拟负荷调整 |

## 四、预处理管线设计

### 4.1 管线流程

```
原始多变量时序 (F, T_top, L, B, Purity)
    │
    ├── Step 1: 缺失值插补 (线性插值)
    │      填补 NaN，保持序列长度不变
    │
    ├── Step 2: 互相关时延估计
    │      对每个变量，计算与纯度在 [0, maxLag] 范围内的
    │      皮尔逊相关系数，取相关性最大的 lag 作为时延
    │
    ├── Step 3: 时序截取 (⭐ 核心贡献)
    │      ├── 时延对齐截取: 各变量按估计时延对齐后提取窗口
    │      ├── 固定窗口截取: 所有变量在同一时间点截取 (对比基线)
    │      └── 事件驱动截取: 检测到跳变后截取过渡段
    │
    ├── Step 4: 滑动平均滤波
    │      窗口大小=5，抑制高频噪声
    │
    └── Step 5: 特征工程
            每个窗口提取: 均值/标准差/最小/最大/斜率/极差
            输出: [样本数 × 特征数] 矩阵
```

### 4.2 三种截取策略详解

#### 策略一：固定窗口截取（对比基线）

```
输入: [x(t-L+1), ..., x(t)] ──► 预测 y(t)
特点: 所有变量用同一时间窗口，实现最简单
缺点: 忽略变量间因果时延差异
适用: 数据采样率低、过程动态慢的场景
```

#### 策略二：时延对齐截取（✅ 推荐）

```
输入: [x₁(t-τ₁-L+1), ..., x₁(t-τ₁),
       x₂(t-τ₂-L+1), ..., x₂(t-τ₂),
       ...]
       ──► 预测 y(t)
特点: 各变量按各自的最优时延对齐后再截取
优点: 因果对齐，物理意义清晰
适用: 精馏塔等多变量有时延差异的过程
```

#### 策略三：事件驱动截取

```
检测: |dF/dt| > threshold
动作: 在事件点后截取一个完整窗口
特点: 聚焦过渡过程，样本量少但信息密度高
适用: 故障诊断、工况切换分析
```

## 五、模型评估结果

### 5.1 精馏塔纯度预测结果

| 模型 | R² | RMSE | 说明 |
|------|:--:|:----:|------|
| RF + 固定窗口 | ~78% | ~2.0% | 简单基线，忽略时延 |
| RF + 时延对齐 | ~77% | ~2.0% | 可解释性强，物理一致 |
| 线性回归 | ~86% | ~1.6% | 数据线性成分较强 |

### 5.2 结果分析

1. **线性回归表现优于 RF**：当前模拟数据中的非线性强度有限（简化模型以线性项为主），在真实工业数据中非线性更强时，RF 的优势会更明显。

2. **时延对齐 vs 固定窗口**：两者在 R² 上相差不大，因为：
   - 进料流量和塔顶温度的时延估计偏小（互相关受整体趋势主导）
   - 在实际应用中，结合工艺知识（如根据塔板数和停留时间计算时延）会优于纯数据驱动估计

3. **事件驱动样本量不足**：检测阈值需进一步调优。

### 5.3 特征重要性分析

RF 的特征重要性排序可回答工艺工程师最关心的问题——**"哪个变量对纯度影响最大？"**，从而指导操作优化方向。

## 六、MVP 与拓展路线

### Phase 1: MVP（已完成）

```
├── 数据生成：稳态 + 噪声 + 缺失 + 时延 + 阶跃

```

